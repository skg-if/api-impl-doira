# Date-type mapping

Field-by-field detail for the [`manifestations[].dates`](SKG_IF_DOI_MAPPING_PRODUCT.md#product-entity)
row of the Product entity mapping.

Both DataCite and Crossref distinguish two categories of date: **metadata management dates**
(when the DOI record itself was registered, updated, or re-indexed) and **resource publication
dates** (when the actual paper, dataset, or media object was created or issued). Verified against
`DataCiteAttributes`/`DataCiteToSkgIfMapper#dates` and `CrossrefWork`/`CrossrefToSkgIfMapper#dates`:

| Date type | DataCite REST API (`/dois/{doi}`) | Crossref REST API (`/works/{doi}`) |
|---|---|---|
| Metadata last updated | `data.attributes.updated` | `message.deposited`\* |
| DOI record created | `data.attributes.created` | `message.created` |
| DOI first registered | `data.attributes.registered` | *(no separate concept - same as `created`)* |
| Actual resource date | `data.attributes.dates[]` (filtered by `dateType`) | `message.published-online` / `published-print` / `issued` |
| Resource publication year | `data.attributes.publicationYear`\*\* | `message.issued.date-parts[0][0]` |

\* Not `message.indexed`, even though it looks like a plausible candidate here - see
[known limitations](SKG_IF_DOI_MAPPING_LIMITATIONS.md#known-limitations) for why re-indexing isn't a safe proxy for a metadata
update, and why `deposited` (Crossref's own documented "most recently updated" signal) is used
for `modified` instead.

\*\* Not read by the mapper - `data.attributes.published` (a string, already used as the
`publication` fallback below) carries the same year in the ISO date format SKG-IF expects, so
reading the year-only integer separately would be redundant.

The final row is for real, documented provider fields that have **no SKG-IF date type to map
to at all** - see [known limitations](SKG_IF_DOI_MAPPING_LIMITATIONS.md#known-limitations) for why each is deliberately left
unread. Neither provider has a source for `access`, `decision`, `distribution`, `received`, or
`request` -
see [known limitations](SKG_IF_DOI_MAPPING_LIMITATIONS.md#known-limitations) also for the one near-miss (`embargo`), and for the
fallback-only nature of the DataCite top-level attributes and Crossref's `update-to[]` above.
